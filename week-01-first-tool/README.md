## Concepts (20 min)

- **The vibe coding idea:** Andrej Karpathy coined the term in February 2025. The idea: describe what you want in plain language, let the AI write the code, test whether it works. No syntax memorization required.
- **The 70% problem:** AI is genuinely brilliant at the first 70% of almost any task — the part that follows known patterns. The last 30% — edge cases, judgment calls, deciding what the right thing even is — still requires you. Your job is to cover that 30%.
- **Director / reviewer / curator:** Think of yourself as a film director, not an actor. You do not perform the work; you describe what you want, review what you get, and decide whether it is right.
- **The agent loop:** Claude Code works in a loop: the model reads your message, decides what to do, calls tools (write a file, run code, read output), gets the result back, and decides what to do next. Understanding this loop makes you a better director.
- **Programming with intent:** The shift is from expressing *steps* ("create a variable, loop over the list...") to expressing *outcomes* ("I want something that reads a CSV and shows me the top 5 values"). You are stating what you want, not how to build it.

## Lab (65 min)

### Part 1: Run the starter tool (10 min)

The `starter/` folder contains `word_counter.py` and `sample.txt`. This script was generated by Claude Code from this prompt: *"Write a Python script that takes a text file and tells me how many words it has, and the five words I use most often, ignoring common words like 'the' and 'and'."*

1. Open VS Code.
2. Open the `week-01-first-tool/starter/` folder: **File → Open Folder**.
3. Open a terminal in VS Code: **Terminal → New Terminal**.
4. Run the script:
   ```
   python word_counter.py sample.txt
   ```
5. You should see a word count and a list of the five most common words. If you get an error, read it carefully — error messages almost always tell you exactly what went wrong.

If your command is `python3` instead of `python`, use `python3 word_counter.py sample.txt`.

### Part 2: Modify it with Claude Code (25 min)

Now you will change the tool. You are not writing code — you are directing Claude Code.

1. Open Claude Code in your terminal (type `claude` and press Enter).
2. Navigate to your starter folder if you are not already there.
3. Try each of these modifications, one at a time. After each one, run the script again and check that it works.

   **Modification 1 — Show top 10 instead of 5:**
   > "In word_counter.py, change it to show the top 10 most common words instead of the top 5."

   **Modification 2 — Add sentence count:**
   > "Also count the number of sentences in the file and print that number. A sentence ends with a period, exclamation point, or question mark."

   **Modification 3 — Ask for an explanation:**
   > "Explain each change you made in one sentence each. Keep your explanation in plain language, no jargon."

4. Notice how Claude Code explains what it changed and why. This is part of the review-refine-own cycle you will use all term.

**If something goes wrong:** If the script errors after a change, paste the exact error message back to Claude Code: *"When I run this, I get: [paste error]. Fix it."* Exact error messages give Claude Code what it needs to diagnose the problem.

### Part 3: Try it on your own text (10 min)

1. Find a text file of your own — a document, an email you exported, anything with words in it.
2. Copy it into the `starter/` folder.
3. Run the script on your file:
   ```
   python word_counter.py yourfile.txt
   ```
4. Ask Claude Code to make one more change that would be useful for your specific file.

If you do not have a text file handy, create one: open VS Code, make a new file, paste in a few paragraphs from a Wikipedia article, and save it as `mytext.txt`.

### Part 4: Start your CLAUDE.md (20 min)

`CLAUDE.md` is how you tell Claude Code about your project. By the end of Week 2 you will have a full one; today you are starting the habit.

1. In Claude Code, ask:
   > "Create a file called CLAUDE.md in this folder. Include: what this project is, what language it uses, and one thing I want you to always remember when working on it."

2. Then answer Claude Code's questions or edit the file directly in VS Code.

3. Think about what you want to build this term. It does not have to be final — just write down the idea. Some examples from past students:
   - A tool that reads my work notes and summarizes action items
   - A weekly budget tracker with a simple web interface
   - Something that pulls news headlines on a topic I care about and emails them to me
   - A recipe keeper where I can search by ingredient

You will turn this idea into a formal BRIEF.md in Week 2.
